# PPMd fixtures

Real PPMd streams from independent encoders, for `codec_ppmd_test.cpp`. The
tests take the raw streams out with a minimal parse (7z: a single-file
archive written with `-mhc=off` keeps its packed stream at offset 32, running
`NextHeaderOffset` bytes; ZIP: the data after the local header of the first
method-98 entry; RAR 4: the data after the first file header) and compare the
decoded bytes with content they generate themselves.

Content (synthetic, generated by `gen.py` below and mirrored by the tests):

* `corpus60k.bin`, `corpus100k.bin`: `text_corpus(n)` of `codec_test_util.hpp`
  (words picked by a linear congruential generator) - 60 000 / 100 000 bytes.
* `both.bin`: `text_corpus(40000)` followed by `noise(10000)` (the xorshift noise of
  `../make_tree.py`) - 50 000 bytes; the noise makes small models run out of memory.
* `lorem.txt`: the `lorem.txt` of `../make_tree.py`.

All archives were written in the Docker image `cvt-archive-tools:1` (Debian 12,
linux/amd64; 7-Zip 26.00 `7zz`) or `cvt-rar4:1` (Ubuntu 22.04; RAR 6.23), as
root with `TZ=UTC`, after `touch -d "2021-06-15 12:00:00"` on the inputs.

| --- | --- | --- |

The small models (64 KiB for 7z, 1 MiB for ZIP) all run out of memory: the
same inputs with 64 MiB give smaller output (checked while making them), so
the restart, glue and cut-off paths of the decoders are exercised.

`gen.py` (run as `python3 gen.py <out> corpus|both|lorem <n>`):

```python
import sys
WORDS = ["archive", "stream", "the", "of", "compression", "block", "window", "and", "match", "literal",
         "offset", "length", "data", "table", "Huffman", "symbol", "a", "file", "entry", "header"]

def text_corpus(size):
    state, parts, total = 12345, [], 0
    while total < size:
        state = (state * 1103515245 + 12345) & 0xFFFFFFFF
        w = WORDS[(state >> 16) % len(WORDS)]
        sep = ".\n" if (state >> 8) % 11 == 0 else " "
        parts += [w, sep]
        total += len(w) + len(sep)
    return "".join(parts)[:size].encode()

def noise(count, seed=2463534242):
    out, state = bytearray(), seed
    for _ in range(count):
        state ^= (state << 13) & 0xFFFFFFFF
        state ^= state >> 17
        state ^= (state << 5) & 0xFFFFFFFF
        out.append(state & 0xFF)
    return bytes(out)

name, kind, n = sys.argv[1], sys.argv[2], int(sys.argv[3])
data = {"corpus": lambda: text_corpus(n), "both": lambda: text_corpus(n) + noise(n // 4)}[kind]()
open(name, "wb").write(data)
```

## Interop of our output

* Our var.H encoder (`Method::Ppmd7`) produces byte-for-byte the packed streams
  of `corpus_o6_64k.7z`, `corpus_o32_64k.7z` and `both_o16_64k.7z` when given the
  same order and memory (levels 5, 9 and 7 with `dictionary_size` 64 KiB); the
  test "our var.H encoder writes exactly what 7-Zip writes" checks this. During
  development our level-5 output was also byte-identical to the packed stream
  of `7zz a -t7z -m0=PPMd:o=6:mem=16m -mhc=off` for 4 MB of text and for 1.7 MB
  of text, noise and repeated blocks (several restarts), so 7-Zip decodes it.
* There is no var.I or LZFSE/ADC encoder (decode only).
