# Brotli fixtures

All files were produced in the `cvt-archive-tools:1` container (Debian 12, linux/amd64) with the
Debian packages `brotli`, `libbrotli1` and `python3-brotli`, all version 1.0.9-2+deb12u1, running
as root with `TZ=UTC` in an empty working directory. Inputs are synthetic.

Inputs used below:

- `text_corpus(n)`: the word generator of `core/tests/families/archive/codec_test_util.hpp`
  (`tc::text_corpus`), reimplemented in Python with the same LCG (state 12345, multiplier
  1103515245, increment 12345, 20-word list, `".\n"` when `(state >> 8) % 11 == 0`).
- `records(n)`: `n` 16-byte little-endian records `(i * 3, (i / 7) * 1000, 0x10, 0xEEFF)`
  (`records()` in `codec_brotli_test.cpp`).
- `noise(n)`: the xorshift32 noise of `core/tests/data/archive/make_tree.py`.
- `lib_compress(data, params)`: `libbrotlienc.so.1` through Python `ctypes`
  (`BrotliEncoderCreateInstance`, `BrotliEncoderSetParameter`, then
  `BrotliEncoderCompressStream` with `BROTLI_OPERATION_FINISH`), for parameters the CLI does not
  expose (`BROTLI_PARAM_NPOSTFIX` = 7, `BROTLI_PARAM_NDIRECT` = 8, `BROTLI_PARAM_LARGE_WINDOW` = 6).

## Embedded static dictionary

`core/src/families/archive/codecs/brotli_dictionary.cpp` holds the 122,784-byte static dictionary
of RFC 7932 Appendix A as a byte array. It was produced and checked in the same container in two
independent ways that gave the same SHA-256
(`20e42eb1b511c21806d4d227d07e5dd06877d8ce7b3a817f378f313653f35c70`):

1. read from `libbrotlicommon.so.1` through `ctypes`: `BrotliGetDictionary()` returns the
   dictionary structure; `data_size` bytes from its `data` pointer;
2. reconstructed by decoding: a hand-assembled stream that references every word of every length
   4..24 in order with the identity transform (one meta-block per word, simple prefix codes) was
   decoded with `brotli -d` and with `python3 -c "brotli.decompress(...)"`; the output is the
   dictionary itself.

The bytes were then written out as a C++ array by a small script (not part of the repository).
The 121 word transforms (`brotli_common.cpp`) and the context lookup tables were checked against
`BrotliGetTransforms()` and `_kBrotliContextLookupTable` of the same library; the test
`archive/brotli: embedded tables match libbrotli's` compares SHA-256 values of the dictionary and
of the 2048-byte lookup table (`0e4abc034ef46244934d117f15876cd477d0fb2ac94a023093338e72e37f7ad9`).

## Interop of our output

Our encoder's output was written to a scratch directory and decoded with `brotli -d` 1.0.9 and
`python3 -c "brotli.decompress(...)"` (python3-brotli 1.0.9) in the container; every stream
decoded byte-exactly with both:

- levels 0..9 on three larger inputs (4 MB of manual-page troff text, a 2.6 MB tar of
  documentation and binaries, 1 MB of random bytes): 30 streams;
- levels 0..9, each with the default window and with `dictionary_size` 2000 (window bits 11), on
  six small inputs (empty, one byte, `prose.txt`, `utf8.txt`, 77 kB of text + UTF-8 text + random
  bytes, 70 kB of one repeated byte): 120 streams.

Together they cover window bits 10..22, uncompressed meta-blocks, context-modelled literals (UTF8
and signed modes, up to 32 literal trees), literal block switching, distance context maps,
implicit and explicit distance short codes, and static dictionary references with transforms
(level 9).
